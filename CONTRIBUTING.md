# Working on Kiflet

Kiflet is not open source: see [`LICENSE`](LICENSE). This is for people who
have been asked to work on it. [`AGENTS.md`](AGENTS.md) is the short
version of the same rules.

## Set up

You need Go 1.27 and Docker. Query changes also need
[sqlc](https://sqlc.dev) 1.30, checking the JavaScript needs Node, and the
end-to-end test of the driver app needs Chrome or Chromium.

```bash
make db      # PostGIS on localhost:5434
make seed    # migrate and load a demo company
make run     # http://localhost:8080
```

The demo logins are in [`README.md`](README.md#run-it-locally). SMS, email
and payments are simulated: codes and links are printed in the terminal
running `make run`. `make sandbox` and `make run-sandbox` run the real
provider adapters against the provider sandbox instead.

## Check your change

```bash
make vet
make test                          # unit tests; also parses every template
make test-integration              # over HTTP, against PostGIS
make staging-up && make test-e2e   # production's images and compose file, over HTTPS
make staging-down
node --check internal/web/static/app.js   # and any other script you touched
```

CI runs all of it on every pull request, with gofmt, `sqlc diff`,
govulncheck and shellcheck.

## Send it

- One change, one pull request, on a branch off `main`. CI must pass.
- Merge with a merge commit. Documents quote commit hashes, and squashing or
  rebasing on GitHub changes them.
- Commit subjects read `area: what changed`, in the present tense, and the
  body says why. `fix: put the map library in the repository` is one.
- If someone using or running Kiflet would notice the change, add a line to
  `CHANGELOG.md` under "Unreleased".
- If the change finishes something in `ROADMAP.md`, delete that part of it.
- If the change departs from `docs/functional_requirements.md`, record it
  in that file's Appendix D.

## Rules

### Where code goes

- `internal/service` holds every business rule. Handlers in `internal/web`
  read the request, call a service and render.
- `internal/app` builds the app from its settings. `cmd/server` and the
  integration tests both use it, so new wiring goes there, not in `main.go`.
- `internal/model` holds the statuses and the table of allowed transitions.
  The driver app gets its rules from `/api/v1/driver/config`, which is
  derived from that table. Change the rules there, not in JavaScript.

### The database

- Every query is scoped by company (`tenant_id`). A query that isn't is a
  security bug.
- `internal/db` is generated by sqlc from `sqlc/queries`. Never edit it:
  change the query and run `make sqlc`.
- A migration is one goose file, `<timestamp>_<name>.up.sql`, holding both
  the Up and the Down, written so that running it twice does no harm
  (`IF NOT EXISTS`, `IF EXISTS`, `CREATE OR REPLACE`). Migrations are
  embedded and applied when the app starts.
- `audit_logs` and `shipment_events` are append-only: a trigger rejects
  UPDATE, DELETE and TRUNCATE. The code that has to remove rows (deleting a
  company, retention) runs inside `purgeTx` in `internal/service/data.go`,
  which sets `kiflet.purge` for its transaction only.

### Pages and the driver app

- The Content Security Policy is `script-src 'self'`, so there are no
  inline scripts. Pass data to JavaScript in a
  `<script type="application/json">` block or in `data-` attributes.
- A part of a page that must stay current gets `data-live-region` and an
  `id`. `static/app.js` fetches it again and swaps it in when a WebSocket
  message says something changed. Don't render it in JavaScript.
- A page's own stylesheets (the `head` block) load before `app.css`, so
  `app.css` can restyle vendor widgets such as the map.
- Templates are reloaded from disk with `DEV_RELOAD=true`, which
  `make run` sets, but a template error only shows when the page is
  rendered. `go test ./internal/web/` parses every page.
- Every static file a page, script or stylesheet names must be in
  `internal/web/static`. A test checks.

### Outside services

- The provider sandbox (`internal/sandbox`, `cmd/sandbox`) imports only the
  standard library and `pkg/console`, and a test enforces it. It implements
  the providers' side of each contract on its own, so a mistake on either
  side shows up as a refused call. When a contract changes, change the
  adapter (`pkg/sms`, `pkg/payments`) and the sandbox together, and run
  `make test-integration`.
- Staging is `deployments/docker-compose.prod.yml` with
  `deployments/staging/compose.yml` on top, which only swaps in stand-ins
  for the outside world. Change production's file and staging follows.

### Keeping it clean

- Metrics live in `pkg/metrics`. Label them by route pattern or another
  short fixed list, never by company, user or shipment.
- The Dockerfile and `.github/workflows/ci.yml` name the same Go release,
  the newest. Change them together.
- `CHANGELOG.md` is the only file that may say what the product was called
  before. CI checks.
